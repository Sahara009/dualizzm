# Выкладка на Netlify без терминала

Всё делается мышкой в браузере, примерно 15 минут. Результат: сайт по ссылке вида `https://dualizzm.netlify.app`, по которому можно ходить, класть работы в корзину, оформлять тестовый заказ и заходить в админку.

**Почему Netlify, а не Cloudflare Pages или GitHub Pages.** У сайта есть серверная часть (корзина, заказы, админка, база). GitHub Pages умеет только статические страницы, а Cloudflare Pages запускает код в своей среде, где нет встроенной базы Node. Netlify запускает Next.js целиком, ничего переделывать не нужно.

## Важно: это демо

У Netlify нет постоянного диска. База и загруженные через админку фото лежат во временной папке и **время от времени сбрасываются** к начальному виду (5 работ, черновики текстов и записей «Хроники»). Админка показывает плашку «Демо-режим».

- Работает: все страницы, видео, каталог, корзина, избранное, тестовая оплата, админка.
- Не сохраняется надолго: заказы, сообщения, правки в админке, загруженные фото. Иногда тестовый заказ может «потеряться» между страницами: у Netlify несколько копий сервера, у каждой своя временная база.

Для настоящего магазина: свой сервер (`VPS.md`) или подключение внешней базы.

## Шаг 1. Проект на GitHub (один раз)

1. Зарегистрируйся на [github.com](https://github.com) и установи [GitHub Desktop](https://desktop.github.com).
2. В GitHub Desktop: **File → Add local repository** → выбери папку `dualizzm-src`.
3. Программа скажет, что это ещё не репозиторий: нажми **create a repository**. Имя `dualizzm`, остальное не трогай → **Create repository**.
4. Нажми **Publish repository**. Галочку **Keep this code private** оставь включённой → **Publish**.

Папки `node_modules`, `.next`, `data` и файл `.env.local` на GitHub не попадут: они в `.gitignore`. Так и надо.

## Шаг 2. Сайт на Netlify

1. Открой [app.netlify.com](https://app.netlify.com) → **Sign up → GitHub** (войти через тот же GitHub).
2. **Add new project** (в старом интерфейсе **Add new site**) → **Import an existing project** → **GitHub** → разреши доступ → выбери репозиторий `dualizzm`.
3. Настройки сборки подставятся сами из `netlify.toml` (`npm run build`, Node 22). Ничего не меняй.
4. Там же нажми **Add environment variables** и добавь три переменные:

| Ключ | Значение |
|---|---|
| `ADMIN_PASSWORD` | пароль для входа в админку, нигде больше не используемый |
| `AUTH_SECRET` | любая длинная строка от 32 символов, например из генератора паролей. Без неё админка не откроется |
| `SITE_URL` | пока `https://dualizzm.netlify.app`, поправишь в шаге 3 |

5. **Deploy**. Сборка идёт 3–5 минут, прогресс виден в разделе **Deploys**.

## Шаг 3. Красивый адрес

1. **Project configuration → General → Change project name** → `dualizzm` (если имя занято, придумай другое).
2. Если адрес получился другим, поменяй `SITE_URL`: **Project configuration → Environment variables**.
3. **Deploys → Trigger deploy → Deploy project**, чтобы применить.

Готово: сайт по адресу `https://ИМЯ.netlify.app`, админка: `https://ИМЯ.netlify.app/admin`.

## Как обновлять сайт

Положи новые файлы в папку `dualizzm-src` → в GitHub Desktop появятся изменения → внизу слева напиши пару слов, что поменялось → **Commit to main** → **Push origin**. Netlify сам пересоберёт сайт за пару минут.

## Если что-то не так

- **Сборка упала (Failed).** Открой этот деплой в **Deploys**, скопируй последние строки лога и пришли Камиле.
- **Страницы открываются, но каталог пустой или ошибка 500.** Добавь переменную `AWS_LAMBDA_JS_RUNTIME` = `nodejs22.x` и сделай **Trigger deploy**. Сайту нужен Node 22.13 или новее.
- **В админку не пускает.** Проверь, что заданы `ADMIN_PASSWORD` и `AUTH_SECRET` (не короче 32 символов), и пересобери.

## Свой домен (потом)

**Domain management → Add a domain** → впиши домен → Netlify покажет, какие записи указать у регистратора (reg.ru и т. п.). HTTPS включится сам.
